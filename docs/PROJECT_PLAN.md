## 1. 项目目标

做一款**浏览器内运行、全前端运算、3D 麻将牌表现**的消除游戏：

- 三种规模：简单 8×9、中等 9×12、完整 12×12。
- 核心操作有两种：**点选两张相同的牌消除**；**按住牌沿行/列拖动，带动连续牌串，落点成对后消除**。
- 牌面为 3D 麻将牌（象牙白牌体、雕刻牌面、毛毡桌面、投影与灯光）。
- 所有游戏逻辑（布局生成、合法性判定、拖动、消除、撤销、死局检测、记录）都在前端完成。
- 后端只做静态资源与关卡配置的分发，使用 FastAPI；后端不保存任何对局状态。

目标体验：单局 1–5 分钟，鼠标与触屏都可顺畅操作；规则一眼能懂，拖动机制提供“棋类”式的思考空间。

### 1.1 非目标（本期不做）

- 联机对战、账号体系、排行榜服务端。
- 关卡编辑器、剧情模式、内购/广告。
- 服务端回放校验或反作弊。
- 原生桌面/移动安装包（后续可加打包脚本）。
- 物理引擎（牌不翻滚、不堆叠，位置严格由格子决定）。

## 2. 内容规模

### 2.1 三种模式

| 模式 | 布局（行 × 列） | 牌数 | 牌种 | 每种张数 |
| --- | --- | --- | --- | --- |
| 简单 | 8 × 9 | 72 | 筒 1–9、索 1–9，共 18 种 | 4 |
| 中等 | 9 × 12 | 108 | 筒/索/万 1–9，共 27 种 | 4 |
| 完整 | 12 × 12 | 144 | 筒/索/万 27 种 + 字牌 7 种 + 花牌 8 种 | 见下 |

> 布局按 **行 × 列** 理解：简单为 8 行 9 列（横向），中等 9 行 12 列，完整 12 行 12 列。

### 2.2 完整模式的牌数构成

| 类别 | 牌种 | 张数 |
| --- | --- | --- |
| 筒 1–9 | 9 | 36 |
| 索 1–9 | 9 | 36 |
| 万 1–9 | 9 | 36 |
| 字牌：东、南、西、北、中、发、白 | 7 | 28 |
| 花牌：春、夏、秋、冬、梅、兰、竹、菊 | 8 | 8（各 1 张） |
| **合计** | **42** | **144** |

花牌各只有 1 张，若严格要求“图案完全相同”，完整模式无法凑成 144 张的偶数配对。因此完整模式对花牌采用**同组互配**：

- 季节组：春、夏、秋、冬，四张之间任意两张可配对；
- 花组：梅、兰、竹、菊，四张之间任意两张可配对；
- 跨组不可配对（春 ↔ 梅 不合法）。

这与麻将连连看/上海麻将的常见花牌规则一致，也保证每组张数为偶数。该规则在 `GAME_RULES.md` 中有精确定义，并保留配置项，后续可切换为“全部花牌互配”。

### 2.3 牌面设计

- 筒：环形圆点，蓝/绿/红配色，按 1–9 的传统点位排布。
- 索：竹节短棒，绿/红配色；1 索用简化的鸟形图案。
- 万：上部汉字数字（一–九），下部“萬”，红黑配色。
- 字牌：东/南/西/北为黑字，中为红字，发为绿字，白为蓝色空心框。
- 花牌：春夏秋冬偏青绿，梅兰竹菊偏绛红，角落加小型印章/叶片装饰。
- 牌面全部由 Canvas 2D **程序化生成**（不依赖图片素材），共享纹理缓存；详见 `RENDERING.md`。

> 牌面用繁体“萬”保持传统观感，UI 文案用简体“万”；可在配置中切换。

## 3. 核心玩法摘要

### 3.1 四条主规则

1. **随机布局**：按模式生成牌组、随机打乱、铺满棋盘；保证初始至少存在一个合法操作。
2. **点选消除**：两张**可配对**的牌，若在同一行或同一列，且中间所有格子为空，即可消除。
3. **拖动带牌**：按住一张牌，沿行或列拖动；**拖动方向上连续相邻的牌串**随它一起平移。
4. **落点判定**：松手时，被拖动的牌必须满足规则 2（与新位置上的同牌形成通路），才消除这一对；否则整串牌动画回到原位，棋盘不变。

### 3.2 拖动的精确定义（默认方案）

- 拖动方向在首次超过阈值时锁定为行或列。
- “牌串”= 被按住的牌 + 它在拖动方向上**连续相邻**的所有牌；反方向的牌不动。
- 牌串整体沿方向平移，最多移动到“串头”撞上下一张牌或棋盘边界之前。
- 落点只看**被按住的这张牌**是否与某张可配对牌形成通路；同串其他牌不会各自自动配对。配对对象可以是串外牌，也可以是串内与它紧邻的同类牌（后者在拖动前就可见，随串一起移动）。
- 配对对象优先取当前选中的锚牌；否则取最近的可见同牌（详见规则文档）。
- 平移动画结束后若不成对，整串回到起点，不进入历史记录。
- 初始棋盘为满盘，所有方向都没有空格，因此**开局的第一步一定是不拖动的点选**；消出空位后拖动才可用。

> 这是一处需要用户确认的规则解释：当前按“**推**”理解——被按住的牌位于移动牌串的尾部，把前方的连续牌一起推走。若改为“拉”（牌在串头、后方的牌跟随），只需调整牌串构造方向，其余规则不变。

### 3.3 胜负与死局

- 所有牌消除完毕即胜利，记录用时与模式。
- 棋盘上既没有可点选的对子、也不存在任何能通过一次拖动成对的操作时，判定为死局；提供撤销上一步、重开本局或换一局。
- **本期不提供洗牌**（也不做任何棋盘重排）；死局不改变棋盘。
- 不承诺“任意随机布局必然可解”；通过死局检测 + 撤销 + 重开/换一局保证玩家不会卡在无操作状态。

### 3.4 随机种子与开局

- 主菜单提供「种子（可选）」输入：**留空 = 随机**；可输入十进制 `0–4294967295`，或 `0x` 开头的十六进制。
- 种子只决定**初始牌序**；同一模式 + 同一种子 = 同一初始布局，牌数、牌种、规则都不变。
- 游戏内显示 8 位十六进制种子（如 `#A1B2C3D4`），支持**复制种子**与**复制分享链接**（`?mode=full&seed=2712847316`）。
- 「重开本局」使用同一 seed；「换一局」生成新 seed（随机来源）。
- **自定义种子开局不计入最佳记录**；只有留空随机开局才计入，避免用简单种子刷记录。
- 同一 seed 的再次开局（重开本局、结算页“同种子再来”）也视为自定义，不再计入记录；只有「换一局」恢复随机资格。
- 种子输入非法（超范围、非数字、负号等）时，输入框内联报错，不开始游戏。

开局与重开流程：

```ts
// 主菜单「开始」
const parsed = parseSeedInput(seedInput);       // '' -> { seed: null }
if (!parsed.ok) return showSeedError(parsed.error);
const seed = parsed.seed ?? randomSeed();
const seedSource = parsed.seed === null ? 'random' : 'custom';
session.start({ mode, seed, seedSource });
syncUrl(mode, seed);                            // history.replaceState

// 「重开本局」：同 seed，标记为 custom（同种子不再计入记录）
session.start({ mode, seed: session.seed, seedSource: 'custom' });

// 「换一局」：新随机 seed，恢复 random 资格
session.start({ mode, seed: randomSeed(), seedSource: 'random' });
```

## 4. 技术选型

| 层 | 选型 | 版本基线 | 理由 |
| --- | --- | --- | --- |
| 前端框架 | Vue 3 + Composition API | `^3.5.44` | 与参考项目一致；HUD/弹窗/菜单用组件化更省事 |
| 构建 | Vite | `^8.3.5` | 当前版本；Node 24 满足其 engines 要求 |
| 语言 | TypeScript | `~5.9.3` | 核心规则需要类型约束；暂不升 TS 7，避免与 vue-tsc 的语言服务兼容风险 |
| 3D | Three.js | `^0.186.1` | WebGL2 渲染、PBR、阴影、Raycaster 均成熟 |
| 状态 | Pinia | `^4.1.0` | 菜单/设置/HUD 与引擎状态解耦 |
| 单元测试 | Vitest | `^5.0.5` | 与 Vite 同生态，纯 TS 核心可直接测 |
| UI 样式 | 原生 CSS + 设计变量 | — | 游戏 UI 定制性强，避免 Tailwind 4 的额外构建链；用 scoped CSS + tokens |
| 后端 | FastAPI + Uvicorn | 最新稳定版 | 只做配置/静态资源分发，轻量 |
| 音频 | Web Audio 程序化合成 | — | 点击/消除/错误音无需素材，后续可换资源文件 |
| 持久化 | `localStorage` | — | 设置、最佳记录；不上传服务端 |

不引入物理引擎、不引入 React Three Fiber、不引入大型动画库；拖拽与补间用一个小型 Tween/Spring 管理器即可。

### 4.1 版本锁定策略

- `frontend/package.json` 使用上面的版本范围，提交 `package-lock.json`。
- 不在本期升级 TypeScript 7 / Tailwind / pnpm；如要升级，先跑通构建与单测。
- `three` 按 minor 锁定（`~0.186.1` 或精确版本），避免 addons 路径与 API 漂移。

## 5. 系统架构

```
┌──────────────────────────── 浏览器（全部游戏逻辑） ────────────────────────────┐
│                                                                              │
│  Vue UI                    Pinia Store                  Three.js Renderer    │
│  ├ MainMenu                ├ phase / stats              ├ Scene / Camera      │
│  ├ GameView / HUD          ├ settings / records          ├ TileFactory        │
│  └ Dialogs                 └ session snapshot            ├ FacePainter        │
│         │                        │                       ├ Input (Raycaster)  │
│         │  commands              │  events               └ Effects / Tweens   │
│         ▼                        ▼                             ▲               │
│  ┌──────────────────────── GameSession（纯 TS 核心）────────────────────────┐  │
│  │ generate / tap / drag / resolve / undo / hint / deadlock                 │  │
│  └──────────────────────────────────────────────────────────────────────────┘  │
│                              │ 只读快照                                        │
│                              └──────────────► Renderer 构建/更新场景            │
└──────────────────────────────┬───────────────────────────────────────────────┘
                               │ HTTP：GET /api/config、/api/assets/*、/api/health
┌──────────────────────────────▼───────────────────────────────────────────────┐
│ FastAPI（无游戏状态）                                                          │
│  ├ /api/config        模式、规则参数、版本                                     │
│  ├ /api/assets/{path} 音频/贴图等静态资源（白名单 + 防目录穿越）                │
│  ├ /api/health        存活探针                                                │
│  └ /                  生产模式托管 frontend/dist 的 SPA                        │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 5.1 边界与不变量

- `src/core/**` 是纯 TypeScript：**不得 import three、不得访问 DOM/window**，保证可在 Node 下测试。
- `GameSession` 是唯一权威状态；Renderer 只读快照、只播放动画，绝不修改棋盘。
- Vue store 保存可序列化快照与 UI 状态；不把 Three.js 对象放进响应式系统（避免 Proxy 性能问题）。
- 所有随机性走可注入种子的 PRNG；同一 seed + 同一操作序列 = 同一结果，便于测试与复现。
- 后端不接收对局操作；刷新即重开（本期不做断点续局）。

### 5.2 一次操作的数据流

1. 指针事件 → `InputController` 命中牌 → 生成 `tap(row,col)` / `dragStart` / `dragMove(k)` / `dragEnd` 意图。
2. `GameSession` 校验并计算新状态；成功消除时追加历史快照。
3. Session 发出事件（`pair:matched`、`drag:reverted`、`game:won`、`game:deadlock`）。
4. Renderer 播放对应动画；Store 更新 HUD；Timer 继续。
5. 动画锁释放后接受下一次输入。

## 6. 前端设计

### 6.1 目录分层

```
src/
├── core/          纯逻辑，无渲染依赖，可单测
├── render/        Three.js 场景、牌、牌面、动效、输入拾取
├── components/    Vue 组件（菜单、HUD、弹窗）
├── stores/        Pinia：对局 UI 状态、设置、本地记录
├── utils/         URL/剪贴板等浏览器工具
├── api/           后端配置/资源客户端
├── styles/        设计变量与全局样式
├── App.vue
└── main.ts
```

### 6.2 核心模块（`core/`）

| 模块 | 职责 |
| --- | --- |
| `types.ts` | `Suit`、`TileKind`、`Tile`、`BoardSnapshot`、`Phase`、`MoveResult` 等 |
| `kinds.ts` | 42 种牌的目录、分组、张数、显示名、牌面绘制键 |
| `rng.ts` | 可播种 PRNG（mulberry32）、随机打乱 |
| `seed.ts` | 种子解析/校验（十进制、`0x` 十六进制）、格式化、随机种子生成 |
| `board.ts` | 不可变棋盘操作：读格、取行/列、移动、删除、统计 |
| `generate.ts` | 按模式构建牌袋、随机打乱、铺盘、保证初始可玩 |
| `rules.ts` | `compatible`、`visible`、`findVisiblePartners`、`findAnyTap` |
| `drag.ts` | 牌串计算、最大滑动量、模拟移动、落点配对选择 |
| `session.ts` | 状态机、操作入口、`start({mode, seed, seedSource})`、历史、提示、死局/胜利判定、统计 |
| `hint.ts` | 优先返回点选对子，否则搜索一次可成对的拖动 |

> `src/utils/url.ts` 不属于 core：负责解析/生成 `?mode=...&seed=...` 分享链接、复制种子到剪贴板等浏览器能力。

### 6.3 渲染模块（`render/`）

| 模块 | 职责 |
| --- | --- |
| `GameRenderer.ts` | 创建 WebGLRenderer/Scene/Camera、RAF 主循环、Raycaster/指针手势、选中/搭档高亮、ghost、dispose |
| `layout.ts` | 格子尺寸、棋盘坐标、世界坐标 ↔ 格坐标 |
| `tileFactory.ts` | 牌体几何、材质、牌面 Mesh、共享资源缓存 |
| `facePainter.ts` | 42 种牌面的 Canvas 绘制与纹理缓存（调试画廊 M5） |
| `tween.ts` | 轻量补间、缓动函数、动画队列 |
| `table.ts` | 毛毡桌面、木质围边、背景与雾 |

### 6.4 UI 组件

- `MainMenu.vue`：标题、三张模式卡（含网格缩略图/记录）、种子输入。
- `SeedInput.vue`：种子输入框、清空按钮、内联校验错误。
- `GameView.vue`：承载 canvas 与 HUD，管理开局/重开/换一局/暂停/撤销/提示/道具，驱动 Renderer。
- `HudBar.vue`：剩余牌数/对数、用时、种子 chip（点击复制）、移牌/撤销/提示/重开。
- `GameDialog.vue`：胜利/死局（显示种子、复制链接、移牌/撤销上一步/同种子再来/换一局）、暂停、重开确认。
- `Toast.vue`：轻提示（“无法消除”“落点无法配对”“种子已复制”）。
- 开发期 `FaceGallery`（`?faces=1`，M5）：一次查看 42 张牌面。

### 6.5 状态管理

`stores/game.ts` 负责：

- 当前模式、`phase`、剩余数量、计时器、连击；
- 种子输入值、`seedSource: 'random' | 'custom'`、当前 seed、解析错误；
- 撤销/提示的可用次数；
- 设置（音效、画质、动效强度）与本地最佳记录（仅随机种子局计入）；
- 启动时读取 URL `?mode=&seed=` 预填；开局后用 `history.replaceState` 同步 URL；
- URL 的 `mode` 必须是 `easy|medium|full`，`seed` 必须通过与输入框相同的校验；无效参数忽略并给轻提示，不阻止进入菜单；
- 缺少 `mode` 时默认 `easy`；缺少 `seed` 时留空（随机）；
- 刷新页面只会用 URL 预填模式/种子，不恢复对局进度；返回主菜单时清空种子输入（当前种子可在 HUD/结算中复制）；
- 调用 Session 的命令方法，并把 Session 事件映射为 UI 状态。

Session 实例本身放在 `shallowRef`/普通变量中，避免深层响应式代理。

### 6.6 API 客户端

- 启动时 `GET /api/config`，失败则回退到内置默认配置（离线也能玩）。
- 资源失败不阻塞游戏：没有音频就静音，没有贴图就程序化生成。
- 所有请求带超时与一次重试；不发送任何对局数据。

## 7. 后端设计

### 7.1 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | `{status:"ok", version}`，前端心跳/开发探针 |
| GET | `/api/config` | 模式定义、规则参数、资源基路径、版本号 |

  "modes": [

## 8. 数据模型与核心算法

### 8.1 数据模型

```ts
type Suit = 'pin' | 'sou' | 'man' | 'honor' | 'flower';
type FlowerGroup = 'season' | 'blossom';

interface TileKind {
  id: string;            // 'pin-1' | 'sou-9' | 'honor-east' | 'flower-spring'
  suit: Suit;
  rank?: number;         // 1..9，字牌/花牌无
  label: string;         // '一筒' | '東' | '春'
  flowerGroup?: FlowerGroup;
}

interface Tile {
  id: number;            // 全局唯一，用于动画/拾取
  kindId: string;
  row: number;
  col: number;
}

interface BoardSnapshot {
  rows: number;
  cols: number;
  cells: (Tile | null)[]; // 长度 rows*cols，索引 r*cols+c
}

interface GameSnapshot {
  phase: 'idle' | 'won' | 'deadlock';
  board: BoardSnapshot;
  remaining: number;
  pairsRemaining: number;
  selectedId: number | null;
  moves: number;
  elapsedMs: number;
  seed: number;
  seedSource: 'random' | 'custom';
}
```

### 8.2 关键算法

| 算法 | 思路 | 复杂度 |
| --- | --- | --- |
| 生成 | 按张数入袋 → 播种打乱 → 行优先铺盘 → 校验存在合法操作，否则重新生成 | O(N) + 重试 |
| 可见性 | 同行/列，检查中间格全空 | O(max(R,C)) |
| 拖动牌串 | 从按下格沿方向收集连续占用格 | O(max(R,C)) |
| 最大滑动 | 从串头向外数连续空格，遇牌/边界停止 | O(max(R,C)) |
| 落点配对 | 在新行/列找可配对且可见的牌；锚牌优先，否则最近 | O(N²) 最坏，N≤144 |
| 死局检测 | 先找点选对子；再枚举每张牌 × 4 方向 × k，模拟后查配对 | O(N × 4 × D × (R+C))，毫秒级（目标 < 5ms） |
| 撤销 | 每步保存完整 `BoardSnapshot`（≤144 项），环形缓冲 50 步 | O(N) 恢复 |

### 8.3 状态机

```
idle ──tap(不成对)──► idle(选中)
idle(选中) ──tap(成对)──► resolving ──► idle | won | deadlock
idle ──dragEnd(成对)──► resolving ──► idle | won | deadlock
idle ──dragEnd(不成对)──► idle（回弹）
resolving / won / deadlock：拒绝新输入
```

- 所有消除后触发一次死局检测（胜利优先）；撤销后做一次保护性检测。
- 动画期间输入被忽略，但指针可以提前按住；动画结束后再判定（可选优化）。

## 9. 3D 表现方案（摘要）

- 牌**平躺**在毛毡桌面上，相机约 75° 俯视，透视投影；所有牌面始终可读。
- 牌体为圆角长方体（约 0.92 × 0.34 × 1.15），象牙白 PBR 材质，顶面覆盖程序化牌面纹理。
- 桌面：深墨绿毛毡 + 深色木质围边 + 轻微雾效；暖色主光 + 冷色补光 + 环境反射。
- 交互反馈：悬停抬升、选中抬升+金色光环、可配对牌脉冲标记、拖动牌串抬升+目标格幽灵、消除金色粒子、无效红色抖动。
- 相机按棋盘尺寸自动适配，横竖屏均完整入画；指针轻微视差，拖拽时关闭。
- 性能预算：144 张牌、约 300 draw call 以内、DPR 上限 2、阴影 2048（可降至 1024/关闭）、目标 60fps。

细节（尺寸、相机公式、纹理规格、动效时长、性能降级策略）见 `docs/RENDERING.md`。

| 事件 | 反馈 |

| 悬停牌 | 抬升 + 边缘高光 + 指针变为可点 |

- 关键词：**墨绿毛毡、象牙牌面、鎏金描边、深夜棋牌室**。

- 断点：≥1280 桌面、768–1279 平板、<768 手机；手机端 HUD 收窄、按钮下移、相机重算。

- 牌面同时用图形与文字区分，不只依赖颜色；按钮有可读标签与焦点样式。

### 10.5 本地记录

- `localStorage` 键：`mahj.settings.v1`、`mahj.records.v1`。
- 记录：各模式最佳用时、完成次数；**只统计随机种子开局**（`seedSource === 'random'`），重开/同种子再来视为自定义。
- 自定义种子完成的局会在结算里标注“自定义种子 · 不计入最佳”，避免用简单种子刷记录。
- 设置：音效开关、画质（高/中/低）、动效强度、相机视差开关。

## 14. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 拖动语义（推/拉）理解偏差 | 核心玩法手感不同，返工 | 规则文档写死默认“推”；牌串构造集中在一个函数，改“拉”只改一处；尽早让用户试玩确认 |
| 自定义种子刷记录 | 记录失真 | 自定义种子开局不计入最佳，结算标注“自定义种子” |
| 随机布局出现死局 | 玩家卡死 | 初始与每步后检测；移牌（每局 3 次）/ 撤销上一步 / 重开 / 换一局；不提供洗牌；不承诺必然可解 |
| 花牌严格配对在 144 张下不可行 | 完整模式无法成对 | 采用季节组/花组互配，并在规则文档解释；保留配置 |
| 42 种程序化牌面工作量大、易丑 | 观感差 | 先做形状母版 + 参数化点位；开发期牌面画廊逐张验收；不行再退回 SVG/贴图资源 |
| 3D 性能不足（低端核显/手机） | 掉帧 | DPR 上限、阴影档位、粒子数量、自适应降级；draw call 预算监控 |
| 牌面中文字体缺失/差异 | 字牌显示错乱 | 字体回退链 + Canvas 测量兜底；后续可内置子集字体 |
| Node/Vite/TS 版本快速演进 | 构建失败 | 锁定版本与 lockfile；升级前跑构建+单测 |
| sandbox 下 npm/pip 缓存不可写 | 依赖装不上 | 项目内缓存目录（`.npm-cache`、`.uv-cache`）；见 `DEVELOPMENT.md` |
| 无浏览器自动化（本会话） | 无法自动截图验收 | 提供 WebGL 检查页与手动回归矩阵；必要时切完全权限后跑 Playwright |

## 16. 开发环境

要求、安装与命令见 `docs/DEVELOPMENT.md`。要点：

- Node.js 24 + npm 11 + Python 3.13；**统一用 npm**（不引入 pnpm）。
- 需要 WebGL2 浏览器（Edge/Chrome 最新版）；牌面/渲染依赖真实 GPU。
- 受限环境（DSH 沙箱）使用项目内缓存与 `dev:sandbox` / `build:sandbox` / `test:sandbox`；普通环境直接用 `dev` / `build` / `test`。
- 一次性的机器审计与权限修复记录不进入仓库。
