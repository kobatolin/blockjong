## 1. 术语与坐标

| 术语 | 含义 |
| --- | --- |
| 棋盘 | `rows × cols` 的矩形格阵，初始**满盘**（每格一张牌） |
| 格 | `(r, c)`，`r` 为行（0 在上），`c` 为列（0 在左） |
| 牌 | 占据一个格，具有唯一 `id` 与牌种 `kindId` |
| 牌种 | 筒/索/万的 1–9、字牌 7 种、花牌 8 种，共 42 种 |
| 可配对 | 两张牌牌种相同；或两张花牌属于同一花组（见 §2.2） |
| 同类（口语） | 本文中泛指“可配对”：同牌种，或同组花牌；不要求牌面完全相同 |
| 可见 | 两张牌同行或同列，且两格之间的所有格为空 |
| 锚牌 | 当前被点选、作为第一张的牌（最多一张） |
| 牌串 | 拖动时一起移动的连续牌集合 |
| 滑动量 `k` | 牌串沿拖动方向平移的格数，整数 |

坐标只用于逻辑；渲染时 `x = c × 格宽`，`z = r × 格深`。

### 1.1 行/列方向

```ts
type Dir = 'left' | 'right' | 'up' | 'down';
const DELTA = {
  left:  { dr: 0,  dc: -1 },
  right: { dr: 0,  dc: +1 },
  up:    { dr: -1, dc: 0 },
  down:  { dr: +1, dc: 0 },
};
```

行方向拖动（left/right）改变列坐标；列方向拖动（up/down）改变行坐标。

### 1.2 种子与复现（开局参数）

- 种子是**无符号 32 位整数**（`0`–`4294967295`），只决定初始牌序；不改变牌数、牌种、可见性、拖动或配对规则。
- 开局时可选输入：
  - 十进制，如 `12345`；
  - `0x` 开头的十六进制，如 `0xA1B2C3D4`；
  - **留空** → 由 `crypto.getRandomValues` 生成随机种子。
- 同一模式 + 同一种子 → 完全相同的初始棋盘；同一操作序列 → 相同结果。
- 显示为 `#` + 8 位大写十六进制（如 `#00003039`）；复制为 `0x00003039`。
- 输入校验：只接受上述格式；超出 `0xFFFFFFFF`、负数、其他字符 → 拒绝并提示。
- `0` 是合法种子，不能用 `0` 表示“未输入”；“未输入”用 `null` 表示。
- 「重开本局」使用同一种子；「换一局」生成新种子。
- **自定义种子**（输入过种子）完成的对局不计入最佳记录；留空随机开局才计入。
- 同一 seed 的再次开局（重开本局、同种子再来）也视为自定义，不再计入记录；只有「换一局」恢复随机资格。

## 2. 牌组与配对

### 2.1 模式与张数

| 模式 | 行 × 列 | 牌数 | 牌种与张数 |
| --- | --- | --- | --- |
| 简单 | 8 × 9 | 72 | 筒 1–9 + 索 1–9，每种 4 张（18 × 4） |
| 中等 | 9 × 12 | 108 | 筒/索/万 1–9，每种 4 张（27 × 4） |
| 完整 | 12 × 12 | 144 | 筒/索/万 27 种 × 4 = 108；字牌 7 种 × 4 = 28；花牌 8 种 × 1 = 8 |

所有模式下每种牌的初始张数必须为偶数（花牌按“组”计为 4 张），保证最终可以全部消完。

### 2.2 花牌的分组配对

完整模式中，8 张花牌各只有 1 张：

| 组 | 牌 | 张数 |
| --- | --- | --- |
| 季节组 `season` | 春、夏、秋、冬 | 4 |
| 花组 `blossom` | 梅、兰、竹、菊 | 4 |

配对判定：

- 两张**同组**花牌可以配对（春 ↔ 夏、春 ↔ 冬、梅 ↔ 菊 等）；
- 不同组花牌不能配对（春 ↔ 梅 不合法）；
- 花牌不能与任何非花牌配对。

> 该规则是完整模式在 144 张下可全消的必要设计。配置项 `flowerMatch` 默认 `"group"`；若改为 `"any"`，则 8 张花牌任意两张可配对，但季节/花组的区分只保留在牌面上。

### 2.3 可配对的判定函数

```ts
function compatible(a: Tile, b: Tile): boolean {
  if (a.id === b.id) return false;
  if (a.kindId === b.kindId) return true;
  const ka = KIND[a.kindId], kb = KIND[b.kindId];
  if (ka.suit === 'flower' && kb.suit === 'flower') {
    return ka.flowerGroup === kb.flowerGroup; // group 模式
  }
  return false;
}
```

注意：同 `kindId` 的牌天然可配对；花牌的 `kindId` 各不相同，因此依赖花组判断。

## 3. 规则 2：可见性与消除

### 3.1 可见

两张不同的牌 `a`、`b` 可见，当且仅当：

1. `a.r === b.r`（同行）或 `a.c === b.c`（同列）；
2. 两格之间的**所有**格为空。

形式化：

```ts
function visible(board, a, b): boolean {
  if (a.id === b.id) return false;
  if (a.r === b.r) {
    const [lo, hi] = [Math.min(a.c, b.c), Math.max(a.c, b.c)];
    for (let c = lo + 1; c < hi; c++) if (board.at(a.r, c)) return false;
    return true;
  }
  if (a.c === b.c) {
    const [lo, hi] = [Math.min(a.r, b.r), Math.max(a.r, b.r)];
    for (let r = lo + 1; r < hi; r++) if (board.at(r, a.c)) return false;
    return true;
  }
  return false;
}
```

要点：

- **空格不阻挡**。两张牌之间可以有任意多个空格，只要没有其他牌。
- **相邻即通**。相邻两格之间没有格子，直接可见。
- **不绕行、不拐弯、不穿边界**。L 形、斜线、跨边界都不算。
- 只检查中间格，不检查两端（两端就是这两张牌本身）。

### 3.2 消除

当两张牌**可配对且可见**时，点选第二张即消除：

- 两张牌从棋盘移除，格子变空；
- 其他牌**不下落、不补位**（与重力消除不同）；
- 剩余牌数减 2，成功消除计数（步数）加 1；
- 触发一次死局/胜利检测。

### 3.3 单张辅助消除（click-click）

当两张牌**可配对但不直接可见**时，如果其中一张牌可以**单独滑动**（移动集合只包含它自己）到某个位置，并与另一张形成可见配对，那么依次点击这两张牌时，直接完成这次单张滑动并消除，不需要再执行拖动：

- 只允许**单张牌**移动；若滑动需要推动连续牌串，则不触发，仍按普通拖动处理。
- 滑动步数 `k ≥ 1`；优先使用第一张锚牌可移动的方案，否则尝试第二张；同一张牌优先最短滑动。
- 只对**当前选中的这两张牌**生效；不会改为去配对其他第三张牌。
- 成功后：两张牌消除，`moves += 1`，历史栈记录**滑动前**的棋盘；撤销会同时还原滑动和消除。
- 若不存在这种单张滑动，仍按 §6.1 切换锚牌，并提示“中间有牌挡住”。

## 4. 规则 3/4：拖动与落点

### 4.1 手势阶段

1. **按下**：指针落在某张牌上，记录起点；此时尚未进入拖动。
2. **超过阈值**：指针位移超过 `DRAG_THRESHOLD`（默认 6 CSS px），根据位移的主轴确定方向，锁定为行或列方向，并锁定正负方向。
3. **拖动中**：计算滑动量 `k` 并实时预览；`k` 始终被限制在 `[0, kMax]`。
4. **松手**：
   - `k === 0`：视为一次点选（见 §6.1），不消除；
   - `k > 0`：提交移动 → 判定落点 → 成功消除或整串回弹。

方向锁定后，若指针回退越过起点，`k` 保持 0，不会反向拖动；这是为了手感稳定。

### 4.2 牌串（移动集合）

设按下的牌为 `t(r, c)`，锁定方向为 `d`（单位向量）。

> **牌串 = 从 `t` 出发、沿 `d` 方向连续相邻的所有牌（含 `t` 本身）。**

```ts
function segment(board, t, d): Tile[] {
  const cells = [t];
  let cur = t;
  while (true) {
    const n = step(cur, d);
    if (!inBounds(n) || !board.at(n)) break;
    cells.push(board.at(n));
    cur = n;
  }
  return cells;
}
```

- 牌串是一个**连续的刚性整体**，平移时内部相对位置不变。
- **反方向**的牌不属于牌串，保持不动。
- 牌串的“串头”是 `d` 方向上最远的那张牌；“串尾”是 `t`。

示例（向右拖，`A` 为按下的牌）：

```
拖动前：  ·  A  B  C  ·  ·  D
牌串：       [A  B  C]
串头 C 右侧有 2 个空格，故 kMax = 2
k = 2：   ·  ·  ·  A  B  C  D
```

### 4.3 最大滑动量 `kMax`

从**串头**的下一格开始，沿 `d` 数连续空格，直到遇到牌或棋盘边界：

```ts
function maxSlide(board, seg, d): number {
  let n = step(seg[seg.length - 1], d);
  let k = 0;
  while (inBounds(n) && !board.at(n)) { k++; n = step(n, d); }
  return k;
}
```

- 若串头已经贴边，或串头前方紧邻一张牌（不可能，因为连续会并入牌串），`kMax = 0`。
- 移动不能越过、推挤或替换任何牌；只能进入空格。
- 满盘时任何方向都 `kMax = 0`，因此**开局只能点选**，必须先消出空格才能拖动。

### 4.4 提交与判定

松手时取最终 `k`：

1. 把牌串整体沿 `d` 平移 `k` 格，得到**预览棋盘**（此时还未写入权威状态）。
2. 被按下的牌落到 `t'(r', c')`。
3. 在预览棋盘中寻找 `t'` 的可配对对象：
   - 候选 = 所有与 `t'` 可配对且可见的牌，**包括随牌串一起移动的牌**（串内只有与 `t'` 紧邻的同类牌才可能可见）；
   - 若当前有锚牌且它在候选中 → 选锚牌；
   - 否则选候选里曼哈顿距离最近的一张（距离相同按 `r`、`c` 升序，保证确定性）。
4. **有候选**：
   - 若候选只有一张，或当前锚牌本身在候选中：直接消除 `t'` 与该牌，提交预览棋盘；牌串中除这两张外的其余牌**留在新位置**。
   - 若候选有两张及以上，且锚牌不在候选中：**不立即消除**，进入 §4.4.1 的“多候选待选”状态。
5. **无候选**：丢弃预览，整串牌动画回到原位，权威棋盘不变，不记步。

#### 4.4.1 多候选待选

当落点同时能看到多张可配对的牌时，由玩家决定消除哪一张：

- 被拖动的牌/牌串视觉上停在落点，**所有候选牌高亮**；
- 点击任意高亮候选 → 只消除“被拖动的牌 + 该候选”，牌串其余牌留在落点；记 1 步，历史快照取拖动前棋盘；
- 点击任何其它格子或非候选牌 → **整串牌动画归位**，不消除、不记步、不写历史；
- 待选期间不接受新的拖动；撤销会取消待选并归位；提示会要求先完成选择；
- 若当前已有锚牌且在候选中，仍按 4.4 的锚牌优先规则直接消除，不进入待选。

> 若串内紧邻同类与更远的候选同时存在，默认取最近者（通常就是串内那张）。想指定更远的牌，可在拖动前先点选它作为锚牌；若未选锚牌且有多张候选，松手后进入“多候选待选”，由玩家点击选择。

### 4.5 关键不变量

- **配对牌可能在牌串内，也可能在串外。**
  - 串内：只有与 `t'` **紧邻**的同类牌才可能可见（中间隔着牌则被挡）；它会随串一起移动，并与 `t'` 一起消除，牌串其余牌留在落点。
  - 串外：更常见的是异轴配对——行拖动后在同一列找牌，列拖动后在同一行找牌。
  - 无论哪种，**只有被拖动的牌参与落点判定**；牌串中的其他牌不会各自去找配对。
- **同轴拖动不会“新造”同轴配对。**
  - 行拖动改变列 → 可能形成新的纵向配对；
  - 列拖动改变行 → 可能形成新的横向配对；
  - 行拖动不会让同一行两张原本被挡的牌“变成通路”，因为牌串平移不改变同行牌的相对顺序与中间阻挡；
  - 唯一可能成立的同轴配对，是拖动前就已可见的同类牌：在串内则必为紧邻；在串外通常在身后，拖动只会拉大间距；
  - 这条性质可用于提示搜索与规则解释。
- **移动只发生在空格中**，牌串不会穿过其他牌。
- **未成功则不落地**：失败拖动不改变棋盘、不写历史、不记步。

### 4.6 拖动示例

**例 A：纵向拖动，创造横向配对**

```
        c0 c1 c2 c3 c4 c5
r0      ·  ·  ·  ·  ·  ·
r1      A  ·  ·  ·  ·  ·
r2      X  ·  ·  ·  ·  ·
r3      ·  ·  ·  ·  ·  ·
r4      ·  ·  ·  A  ·  ·
r5      ·  ·  ·  ·  ·  ·
```

按住 `A(1,0)` 向下拖：

- 牌串 = `A(1,0), X(2,0)`（r3 为空，断开）；
- 串头 `X` 下方有 r3、r4、r5 三个空格 → `kMax = 3`；
- `k = 3` 后：`A` 到 `(4,0)`，`X` 到 `(5,0)`；
- 第 4 行 `A(4,0)` 与 `A(4,3)` 之间 c1、c2 为空 → 可见 → 消除这一对。

**例 B：横向拖动，创造纵向配对**

```
        c0 c1 c2 c3 c4 c5
r0      ·  A  B  ·  ·  C
r1      ·  ·  ·  ·  ·  ·
r2      ·  ·  ·  ·  ·  ·
r3      ·  ·  ·  A  ·  ·
r4      ·  ·  ·  ·  ·  ·
r5      ·  ·  ·  ·  ·  ·
```

按住 `A(0,1)` 向右拖：

- 牌串 = `A(0,1), B(0,2)`；串头 `B` 右侧 c3、c4 为空，c5 为 `C` → `kMax = 2`；
- `k = 2` 后：`A` 到 `(0,3)`，`B` 到 `(0,4)`；
- 第 3 列 `A(0,3)` 与 `A(3,3)` 之间 r1、r2 为空 → 可见 → 消除。

**例 C：失败回弹**

```
        c0 c1 c2
r0      A  ·  ·
r1      ·  ·  ·
r2      B  ·  ·
```

按住 `A(0,0)` 向下拖 1 格 → `A(1,0)`；第 1 行没有可配对的牌（`B` 在第 2 行），也没有同列可配对牌 → 无候选 → `A` 回到 `(0,0)`，棋盘不变。

> 注意：移动后只看**被拖动牌的新行/新列**。上例中 `A(1,0)` 与 `B(2,0)` 同列，但牌种不同，不算候选。

**例 D：满盘无空格**

```
A B C A
```

任意牌向右拖，牌串直达右边界，`kMax = 0`，不产生移动；松手按点选处理。只有相邻的 `A A`（若存在）可以直接消除。

**例 E：牌串内部本来就有紧邻同类**

```
        c0 c1 c2 c3 c4
r0      A  A  B  ·  C
```

按住 `A(0,0)` 向右拖：

- 牌串 = `A(0,0), A(0,1), B(0,2)`；串头 `B` 右侧 c3 为空，c4 为 `C` → `kMax = 1`；
- `k = 1` 后：`A` 到 `(0,1)`，另一张 `A` 到 `(0,2)`，`B` 到 `(0,3)`；
- 两张 `A` 仍然紧邻 → 可见 → 消除这一对；`B` 留在 `(0,3)`。

> 这是“配对牌在串内”的情况：`A A` 在拖动前就紧邻可见，随串一起移动后仍可消除。另一种同轴配对是配对牌在身后且拖动前就可见——拖动只会拉大间距，仍然可见。两者都不是拖动“新造”的通路。若两张 `A` 之间隔了 `B`，则拖动后仍被 `B` 阻挡，不能配对。

## 5. 一次操作的完整流程

### 5.1 点选

```
tap(t):
  if phase != idle: ignore
  if anchor == null:
      anchor = t; return selected
  if anchor == t:
      anchor = null; return deselected
  if compatible(anchor, t) and visible(anchor, t):
      anchor = null
      remove(anchor, t)
      moves += 1
      check win / deadlock
      return matched
  else:
      anchor = t          // 无论牌种是否相同、是否被挡，都切换为新的锚牌
      return switched
```

> 设计取舍：被挡的同类牌或不同牌都会“成为新锚牌”，而不是保持旧锚牌。这样每次点击都有明确反馈，不会出现“点了没反应”的困惑；阻挡原因用 Toast 说明。

### 5.2 拖动

```
dragEnd(t, d, k):
  if phase != idle: ignore
  seg = segment(t, d)
  k = clamp(k, 0, maxSlide(seg, d))
  if k == 0:
      return tap(t)                 // 松手在原格，视为点选
  preview = slide(seg, k)
  t2 = preview.tileAt(t.dest)
  partner = choosePartner(preview, t2, anchor ? anchor.id : null)
  if partner == null:
      animateRevert(seg)            // 权威棋盘不变
      return reverted               // 锚牌保留，便于重试
  else:
      commit(preview)
      anchor = null
      removePair(t2, partner)
      moves += 1
      check win / deadlock
      return matched
```

### 5.3 消除后的顺序

1. 从棋盘移除两张牌；
2. `remaining -= 2`，`moves += 1`；
3. 若 `remaining === 0` → **胜利**（优先）；
4. 否则做死局检测；若死局 → **死局**；
5. 否则回到 `idle`，允许下一次操作。

### 5.4 动画与逻辑分离

逻辑在松手瞬间即可确定结果；渲染层只是把结果演出来。为保证输入一致性：

- 进入 `resolving` 后拒绝新的点选/拖动；
- 动画结束后释放锁；
- 若玩家在动画期间按下，可缓存“按下”状态，动画结束后再判定（M5 可选优化，MVP 直接忽略）。

## 6. 选择、撤销、提示

### 6.1 选择（锚牌）

- 任何时候最多一张锚牌。
- 锚牌的作用：
  1. 点选第二张时判定配对；
  2. 拖动落点时作为**优先配对对象**（若它在新位置可见且可配对）；
  3. UI 高亮所有与锚牌可见且可配对的牌。
- 点击空白格 → 取消选择。
- 点击锚牌自身 → 取消选择。
- 点击其他牌 → 若与锚牌构成合法对子则消除；否则锚牌切换为该牌。
- 若两张牌不直接可见，但其中一张能**单独滑动**后与另一张配对，则第二次点击直接完成单张滑动 + 消除（见 §3.3）；不需要拖动。
- 成功消除、撤销、重开 → 清空锚牌。

### 6.2 撤销

- 每次**成功消除**前，保存完整 `BoardSnapshot` 到历史栈（最多 50 步）。
- 拖动成功时，快照取**拖动开始前**的棋盘（牌串在原位），而不是落点后的棋盘；这样撤销会同时还原牌串位置与被消除的两张牌。
- 撤销恢复该快照，并恢复 `remaining`、`moves`；**计时不回退**。
- 拖动失败不入历史；撤销队列不包含它。
- 撤销后清空锚牌、提示、连击；若当前是死局/胜利状态，撤销可回到 `idle`（胜利后是否允许撤销由 UI 决定，默认禁止）。
- `moves` 记录成功消除次数；撤销一步时减 1。

### 6.3 提示

- 优先返回一个**点选对子**（任意可见的可配对牌）；
- 若没有，则搜索一个**可成对的拖动**：枚举牌 × 4 方向 × `k ∈ [1, kMax]`，模拟后检查是否能找到配对对象；
- 返回结果用于高亮两张牌或显示“方向 + 目标格”的箭头；
- 默认不限次数、无惩罚（休闲向）；后续可加次数或时间惩罚。
- 提示不改变棋盘，不记步。

## 7. 胜负与死局

### 7.1 胜利

`remaining === 0` 时胜利：

- 停止计时；
- 记录用时、步数、模式；
- 与本地最佳记录比较并更新；
- 播放胜利动画，弹出结算。

### 7.2 死局

当 `remaining > 0`，且以下两类操作都不存在时，判定死局：

1. 任意两张可配对且可见的牌（点选）；
2. 任意一张牌、任意方向、任意 `k ∈ [1, kMax]` 的拖动，落点能找到可配对且可见的牌。

死局处理：

- 弹出对话框：撤销上一步（推荐）、重开本局、换一局（新种子）；
- **不提供洗牌或任何形式的棋盘重排**；棋盘保持原样，由玩家决定回退或重开；
- 若此时没有可撤销的历史（理论上不会：初始布局保证可玩），只能重开本局或换一局；
- 死局期间暂停计时与输入。

> “重开本局”= 同一 `seed` 回到初始布局；“换一局”= 新 `seed`、新随机布局，计时/步数清零。

### 7.3 为什么可能死局

消除顺序会影响后续可见性；随机布局不保证存在一条通关路径。项目**不承诺**任意布局必然可解，而是通过：

- 初始生成时保证至少一个合法操作；
- 每步后的死局检测；
- 撤销上一步 + 重开本局/换一局；

让玩家不会卡在无操作状态。**游戏内不提供洗牌**，死局不会改变棋盘。

> 后续可选：用“逆向摆牌”生成保证可解的布局（从空盘逐步放回可消除的对子），但实现复杂度较高，本期不做。

## 9. 算法伪代码

以下为与实现无关的参考伪代码；TypeScript 实现应保持函数纯粹、无副作用。

### 9.1 生成

```
generate(mode, seed):
  kinds = KINDS[mode]
  bag = []
  for kind in kinds:
      repeat kind.count times: bag.push(kind.id)
  rng = mulberry32(seed)
  for attempt in 1..200:
      randomize(bag, rng)              // 生成用 Fisher-Yates，不是游戏内洗牌
      board = fillRowMajor(bag, mode.rows, mode.cols)
      if findAnyMove(board) != null: return board
  return fallbackPlayableLayout(mode)
```

`seed` 来自 §1.2，必须是 `0..0xFFFFFFFF` 的整数；相同 seed 会得到相同的 `randomize` 序列。

初始棋盘为满盘；`findAnyMove` 在满盘时等价于“存在相邻同类对”（因为任何非相邻牌之间都有牌阻挡）。

`fallbackPlayableLayout(mode)` 是极端兜底：从牌袋中取任意一对可配对的牌放到 `(0,0)`、`(0,1)`，其余按牌袋顺序铺满，保证初始至少有一个相邻对子。正常随机布局几乎不会触发。

> 满盘时所有方向 `kMax = 0`，所以开局第一步必然是不拖动的点选；消出空格后拖动才可用。若产品希望开局即可拖动，需要改为“预留少量空位”的生成方式，并同步调整牌数/测试。

### 9.2 可见

```
visible(a, b):
  if a.row == b.row:
      for c in (min(a.col,b.col)+1 .. max(a.col,b.col)-1):
          if board[a.row][c] != null: return false
      return true
  if a.col == b.col:
      for r in (min(a.row,b.row)+1 .. max(a.row,b.row)-1):
          if board[r][a.col] != null: return false
      return true
  return false
```

### 9.3 牌串与滑动

```
segment(t, d):
  out = [t]; cur = t
  loop:
      n = cur + DELTA[d]
      if outOfBounds(n) or board[n] == null: break
      out.push(board[n]); cur = n
  return out

maxSlide(seg, d):
  n = seg.last + DELTA[d]; k = 0
  while inBounds(n) and board[n] == null:
      k += 1; n += DELTA[d]
  return k

slide(seg, k, d):
  copy = board.clone()
  for tile in reverse(seg):          // 逆序避免覆盖
      copy.move(tile, tile + d*k)
  return copy
```

### 9.4 选配对

```
choosePartner(board, dragged, anchorId):
  cands = []
  // 只需扫描同行与同列：异行异列不可能 visible
  for tile in board.row(dragged.row) + board.col(dragged.col):
      if tile.id != dragged.id
         and compatible(dragged, tile)
         and visible(dragged, tile):
          cands.push(tile)
  if anchorId != null:
      a = board.tileById(anchorId)          // 锚牌可能随牌串移动，用 id 重新定位
      if a != null and a in cands: return a
  if cands.empty: return null
  sort cands by (manhattan(dragged, t), t.row, t.col)
  return cands[0]
```

### 9.5 死局与提示

```
findAnyMove(board):
  // 1) 点选对子
  for each pair (a, b) in board.tiles():
      if compatible(a, b) and visible(a, b): return {kind:'tap', a, b}
  // 2) 拖动
  for each tile t:
      for d in DIRS:
          seg = segment(t, d)
          kmax = maxSlide(seg, d)
          for k in 1..kmax:
              preview = slide(seg, k, d)
              t2 = preview.tileAt(dest(t, k, d))
              p = choosePartner(preview, t2, null)
              if p != null: return {kind:'drag', tile:t, d, k, partner:p}
  return null
```

### 9.6 复杂度

| 操作 | 复杂度 | 备注 |
| --- | --- | --- |
| 生成 | O(N) × 重试 | 重试通常 1 次 |
| 可见性 | O(max(R,C)) ≤ 12 | 极快 |
| 牌串/滑动 | O(max(R,C)) | 极快 |
| 单次落点配对 | O(N²) 最坏 | N ≤ 144，可忽略 |
| 死局检测 | O(N × 4 × D × (R+C)) 最坏 | 目标 < 5ms（D ≤ 12） |
| 撤销 | O(N) | 快照复制 |

## 10. 图例

### 10.1 点选配对

```
· 表示空格，字母表示牌种

A A · B          → A(0,0) 与 A(0,1) 相邻，可消除
A · · A          → 中间全空，可消除
A B · A          → B 阻挡，不可消除
A · B · A        → B 阻挡，不可消除
A · · ·          → 只有一张 A，不能消除
```

### 10.2 拖动牌串与滑动量

```
行：  ·  A  B  C  ·  ·  D
       ↑ 牌串起点（按下 A）
          └──── 牌串 A B C ────┘
                        └ 串头 C
C 右侧空格：2 个（kMax = 2）

k = 1： ·  ·  A  B  C  ·  D
k = 2： ·  ·  ·  A  B  C  D
```

### 10.3 同轴 / 异轴

```
行拖动（左右）改变列 → 可产生“同列”的新配对（纵向）
列拖动（上下）改变行 → 可产生“同行”的新配对（横向）
例外：牌串内本来紧邻的同类牌会随串移动、仍可配对；这不是新造的通路。
```

### 10.4 花牌

```
春 秋  ·  → 同属季节组，可消除
春 梅  ·  → 跨组，不可消除
梅 竹  ·  → 同属花组，可消除
```
