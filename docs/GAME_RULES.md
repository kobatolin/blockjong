## 1. 术语与坐标

| 术语 | 含义 |
| --- | --- |
| 棋盘 | `rows × cols` 的矩形格阵，初始**满盘**（每格一张牌） |
| 格 | `(r, c)`，`r` 为行（0 在上），`c` 为列（0 在左） |
| 牌 | 占据一个格，具有唯一 `id` 与牌种 `kindId` |
| 牌种 | 筒/索/万的 1–9、字牌 7 种、花牌 8 种，共 42 种 |
| 可配对 | 两张牌牌种相同；或两张花牌属于同一花组（见 §2.2） |
| 可见 | 两张牌同行或同列，且两格之间的所有格为空 |
| 锚牌 | 当前被点选、作为第一张的牌（最多一张） |
| 牌串 | 拖动时一起移动的连续牌集合 |
| 滑动量 `k` | 牌串沿拖动方向平移的格数，整数 |

坐标只用于逻辑；渲染时 `x = c × 格宽`，`z = r × 格深`。

### 1.1 行/列方向

```ts
type Dir = 'left' | 'right' | 'up' | 'down';
const DELTA = {
  left:  { dr: 0,  dc: -1 },
  right: { dr: 0,  dc: +1 },
  up:    { dr: -1, dc: 0 },
  down:  { dr: +1, dc: 0 },
};
```

行方向拖动（left/right）改变列坐标；列方向拖动（up/down）改变行坐标。

## 2. 牌组与配对

### 2.1 模式与张数

| 模式 | 行 × 列 | 牌数 | 牌种与张数 |
| --- | --- | --- | --- |
| 简单 | 8 × 9 | 72 | 筒 1–9 + 索 1–9，每种 4 张（18 × 4） |
| 中等 | 9 × 12 | 108 | 筒/索/万 1–9，每种 4 张（27 × 4） |
| 完整 | 12 × 12 | 144 | 筒/索/万 27 种 × 4 = 108；字牌 7 种 × 4 = 28；花牌 8 种 × 1 = 8 |

所有模式下每种牌的初始张数必须为偶数（花牌按“组”计为 4 张），保证最终可以全部消完。

### 2.2 花牌的分组配对

完整模式中，8 张花牌各只有 1 张：

| 组 | 牌 | 张数 |
| --- | --- | --- |
| 季节组 `season` | 春、夏、秋、冬 | 4 |
| 花组 `blossom` | 梅、兰、竹、菊 | 4 |

配对判定：

- 两张**同组**花牌可以配对（春 ↔ 夏、春 ↔ 冬、梅 ↔ 菊 等）；
- 不同组花牌不能配对（春 ↔ 梅 不合法）；
- 花牌不能与任何非花牌配对。

> 该规则是完整模式在 144 张下可全消的必要设计。配置项 `flowerMatch` 默认 `"group"`；若改为 `"any"`，则 8 张花牌任意两张可配对，但季节/花组的区分只保留在牌面上。

### 2.3 可配对的判定函数

```ts
function compatible(a: Tile, b: Tile): boolean {
  if (a.id === b.id) return false;
  if (a.kindId === b.kindId) return true;
  const ka = KIND[a.kindId], kb = KIND[b.kindId];
  if (ka.suit === 'flower' && kb.suit === 'flower') {
    return ka.flowerGroup === kb.flowerGroup; // group 模式
  }
  return false;
}
```

注意：同 `kindId` 的牌天然可配对；花牌的 `kindId` 各不相同，因此依赖花组判断。

## 3. 规则 2：可见性与消除

### 3.1 可见

两张不同的牌 `a`、`b` 可见，当且仅当：

1. `a.r === b.r`（同行）或 `a.c === b.c`（同列）；
2. 两格之间的**所有**格为空。

形式化：

```ts
function visible(board, a, b): boolean {
  if (a.id === b.id) return false;
  if (a.r === b.r) {
    const [lo, hi] = [Math.min(a.c, b.c), Math.max(a.c, b.c)];
    for (let c = lo + 1; c < hi; c++) if (board.at(a.r, c)) return false;
    return true;
  }
  if (a.c === b.c) {
    const [lo, hi] = [Math.min(a.r, b.r), Math.max(a.r, b.r)];
    for (let r = lo + 1; r < hi; r++) if (board.at(r, a.c)) return false;
    return true;
  }
  return false;
}
```

要点：

- **空格不阻挡**。两张牌之间可以有任意多个空格，只要没有其他牌。
- **相邻即通**。相邻两格之间没有格子，直接可见。
- **不绕行、不拐弯、不穿边界**。L 形、斜线、跨边界都不算。
- 只检查中间格，不检查两端（两端就是这两张牌本身）。

### 3.2 消除

当两张牌**可配对且可见**时，点选第二张即消除：

- 两张牌从棋盘移除，格子变空；
- 其他牌**不下落、不补位**（与重力消除不同）；
- 剩余牌数减 2，成功消除计数（步数）加 1；
- 触发一次死局/胜利检测。

## 4. 规则 3/4：拖动与落点

### 4.1 手势阶段

1. **按下**：指针落在某张牌上，记录起点；此时尚未进入拖动。
2. **超过阈值**：指针位移超过 `DRAG_THRESHOLD`（默认 6 CSS px），根据位移的主轴确定方向，锁定为行或列方向，并锁定正负方向。
3. **拖动中**：计算滑动量 `k` 并实时预览；`k` 始终被限制在 `[0, kMax]`。
4. **松手**：
   - `k === 0`：视为一次点选（见 §6.1），不消除；
   - `k > 0`：提交移动 → 判定落点 → 成功消除或整串回弹。

方向锁定后，若指针回退越过起点，`k` 保持 0，不会反向拖动；这是为了手感稳定。

### 4.2 牌串（移动集合）

设按下的牌为 `t(r, c)`，锁定方向为 `d`（单位向量）。

> **牌串 = 从 `t` 出发、沿 `d` 方向连续相邻的所有牌（含 `t` 本身）。**

```ts
function segment(board, t, d): Tile[] {
  const cells = [t];
  let cur = t;
  while (true) {
    const n = step(cur, d);
    if (!inBounds(n) || !board.at(n)) break;
    cells.push(board.at(n));
    cur = n;
  }
  return cells;
}
```

- 牌串是一个**连续的刚性整体**，平移时内部相对位置不变。
- **反方向**的牌不属于牌串，保持不动。
- 牌串的“串头”是 `d` 方向上最远的那张牌；“串尾”是 `t`。

示例（向右拖，`A` 为按下的牌）：

```
拖动前：  ·  A  B  C  ·  ·  D
牌串：       [A  B  C]
串头 C 右侧有 2 个空格，故 kMax = 2
k = 2：   ·  ·  ·  A  B  C  D
```

### 4.3 最大滑动量 `kMax`

从**串头**的下一格开始，沿 `d` 数连续空格，直到遇到牌或棋盘边界：

```ts
function maxSlide(board, seg, d): number {
  let n = step(seg[seg.length - 1], d);
  let k = 0;
  while (inBounds(n) && !board.at(n)) { k++; n = step(n, d); }
  return k;
}
```

- 若串头已经贴边，或串头前方紧邻一张牌（不可能，因为连续会并入牌串），`kMax = 0`。
- 移动不能越过、推挤或替换任何牌；只能进入空格。
- 满盘时任何方向都 `kMax = 0`，因此**开局只能点选**，必须先消出空格才能拖动。

### 4.4 提交与判定

松手时取最终 `k`：

1. 把牌串整体沿 `d` 平移 `k` 格，得到**预览棋盘**（此时还未写入权威状态）。
2. 被按下的牌落到 `t'(r', c')`。
3. 在预览棋盘中寻找 `t'` 的可配对对象：
   - 候选 = 所有与 `t'` 可配对且可见的牌；
   - 若当前有锚牌且它在候选中 → 选锚牌；
   - 否则选候选里曼哈顿距离最近的一张（距离相同按 `r`、`c` 升序，保证确定性）。
4. **有候选**：消除 `t'` 与配对牌，提交预览棋盘，牌串中其余牌**留在新位置**。
5. **无候选**：丢弃预览，整串牌动画回到原位，权威棋盘不变，不记步。

### 4.5 关键不变量

- **配对牌一定不在移动牌串中。**
  - 行拖动时，牌串全在同一行；配对牌必须在新的同一列（纵向），而牌串中只有被拖动的牌可能在该列上。
  - 列拖动同理（配对牌在新行，牌串在同一列）。
  - 因此消除不会误删牌串中的其他牌。
- **同轴拖动只能创造异轴配对。**
  - 行拖动改变列 → 可能形成纵向配对；
  - 列拖动改变行 → 可能形成横向配对；
  - 行拖动不会让同一行的两张牌“从被挡变成通路”，因为牌串平移不改变同行牌的相对顺序与中间阻挡。
  - 这条性质可用于提示搜索与规则解释。
- **移动只发生在空格中**，牌串不会穿过其他牌。
- **未成功则不落地**：失败拖动不改变棋盘、不写历史、不记步。

### 4.6 拖动示例

**例 A：纵向拖动，创造横向配对**

```
        c0 c1 c2 c3 c4 c5
r0      ·  ·  ·  ·  ·  ·
r1      A  ·  ·  ·  ·  ·
r2      X  ·  ·  ·  ·  ·
r3      ·  ·  ·  ·  ·  ·
r4      ·  ·  ·  A  ·  ·
r5      ·  ·  ·  ·  ·  ·
```

按住 `A(1,0)` 向下拖：

- 牌串 = `A(1,0), X(2,0)`（r3 为空，断开）；
- 串头 `X` 下方有 r3、r4、r5 三个空格 → `kMax = 3`；
- `k = 3` 后：`A` 到 `(4,0)`，`X` 到 `(5,0)`；
- 第 4 行 `A(4,0)` 与 `A(4,3)` 之间 c1、c2 为空 → 可见 → 消除这一对。

**例 B：横向拖动，创造纵向配对**

```
        c0 c1 c2 c3 c4 c5
r0      ·  A  B  ·  ·  C
r1      ·  ·  ·  ·  ·  ·
r2      ·  ·  ·  ·  ·  ·
r3      ·  ·  ·  A  ·  ·
r4      ·  ·  ·  ·  ·  ·
r5      ·  ·  ·  ·  ·  ·
```

按住 `A(0,1)` 向右拖：

- 牌串 = `A(0,1), B(0,2)`；串头 `B` 右侧 c3、c4 为空，c5 为 `C` → `kMax = 2`；
- `k = 2` 后：`A` 到 `(0,3)`，`B` 到 `(0,4)`；
- 第 3 列 `A(0,3)` 与 `A(3,3)` 之间 r1、r2 为空 → 可见 → 消除。

**例 C：失败回弹**

```
        c0 c1 c2
r0      A  ·  ·
r1      ·  ·  ·
r2      B  ·  ·
```

按住 `A(0,0)` 向下拖 1 格 → `A(1,0)`；第 1 行没有可配对的牌（`B` 在第 2 行），也没有同列可配对牌 → 无候选 → `A` 回到 `(0,0)`，棋盘不变。

> 注意：移动后只看**被拖动牌的新行/新列**。上例中 `A(1,0)` 与 `B(2,0)` 同列，但牌种不同，不算候选。

**例 D：满盘无空格**

```
A B C A
```

任意牌向右拖，牌串直达右边界，`kMax = 0`，不产生移动；松手按点选处理。只有相邻的 `A A`（若存在）可以直接消除。

## 5. 一次操作的完整流程

### 5.1 点选

```
tap(t):
  if phase != idle: ignore
  if anchor == null:
      anchor = t; return selected
  if anchor == t:
      anchor = null; return deselected
  if compatible(anchor, t) and visible(anchor, t):
      anchor = null
      remove(anchor, t)
      moves += 1
      check win / deadlock
      return matched
  else:
      anchor = t          // 无论牌种是否相同、是否被挡，都切换为新的锚牌
      return switched
```

> 设计取舍：被挡的同类牌或不同牌都会“成为新锚牌”，而不是保持旧锚牌。这样每次点击都有明确反馈，不会出现“点了没反应”的困惑；阻挡原因用 Toast 说明。

### 5.2 拖动

```
dragEnd(t, d, k):
  if phase != idle: ignore
  seg = segment(t, d)
  k = clamp(k, 0, maxSlide(seg, d))
  if k == 0:
      return tap(t)                 // 松手在原格，视为点选
  preview = slide(seg, k)
  t2 = preview.tileAt(t.dest)
  partner = choosePartner(preview, t2, anchor)
  if partner == null:
      animateRevert(seg)            // 权威棋盘不变
      return reverted               // 锚牌保留，便于重试
  else:
      commit(preview)
      anchor = null
      removePair(t2, partner)
      moves += 1
      check win / deadlock
      return matched
```

### 5.3 消除后的顺序

1. 从棋盘移除两张牌；
2. `remaining -= 2`，`moves += 1`；
3. 若 `remaining === 0` → **胜利**（优先）；
4. 否则做死局检测；若死局 → **死局**；
5. 否则回到 `idle`，允许下一次操作。

### 5.4 动画与逻辑分离

逻辑在松手瞬间即可确定结果；渲染层只是把结果演出来。为保证输入一致性：

- 进入 `resolving` 后拒绝新的点选/拖动；
- 动画结束后释放锁；
- 若玩家在动画期间按下，可缓存“按下”状态，动画结束后再判定（M5 可选优化，MVP 直接忽略）。

## 6. 选择、撤销、洗牌、提示

### 6.1 选择（锚牌）

- 任何时候最多一张锚牌。
- 锚牌的作用：
  1. 点选第二张时判定配对；
  2. 拖动落点时作为**优先配对对象**（若它在新位置可见且可配对）；
  3. UI 高亮所有与锚牌可见且可配对的牌。
- 点击空白格 → 取消选择。
- 点击锚牌自身 → 取消选择。
- 点击其他牌 → 若与锚牌构成合法对子则消除；否则锚牌切换为该牌。
- 成功消除、撤销、洗牌、重开 → 清空锚牌。

### 6.2 撤销

- 每次**成功消除**或**洗牌**前，保存完整 `BoardSnapshot` 到历史栈（最多 50 步）。
- 撤销恢复该快照，并恢复 `remaining`、`moves`；**计时不回退**。
- 拖动失败不入历史；撤销队列不包含它。
- 撤销后清空锚牌、提示、连击；若当前是死局/胜利状态，撤销可回到 `idle`（胜利后是否允许撤销由 UI 决定，默认禁止）。
- `moves` 记录成功消除次数；撤销一步时减 1。

### 6.3 洗牌

- 只重排**剩余牌**的牌种，空格位置不变。
- 保持每种牌的张数不变（包括花组数量）。
- 洗牌后必须至少存在一个合法操作；最多重试 100 次，若仍失败则退化为“按对子相邻摆放”的确定性布局。
- 手动洗牌默认 3 次；死局弹窗中的免费洗牌不消耗次数。
- 洗牌本身不增加 `moves`，但计时继续；清空锚牌与提示。
- 洗牌前入历史，可撤销。

### 6.4 提示

- 优先返回一个**点选对子**（任意可见的可配对牌）；
- 若没有，则搜索一个**可成对的拖动**：枚举牌 × 4 方向 × `k ∈ [1, kMax]`，模拟后检查是否能找到配对对象；
- 返回结果用于高亮两张牌或显示“方向 + 目标格”的箭头；
- 默认不限次数、无惩罚（休闲向）；后续可加次数或时间惩罚。
- 提示不改变棋盘，不记步。

## 7. 胜负与死局

### 7.1 胜利

`remaining === 0` 时胜利：

- 停止计时；
- 记录用时、步数、模式；
- 与本地最佳记录比较并更新；
- 播放胜利动画，弹出结算。

### 7.2 死局

当 `remaining > 0`，且以下两类操作都不存在时，判定死局：

1. 任意两张可配对且可见的牌（点选）；
2. 任意一张牌、任意方向、任意 `k ∈ [1, kMax]` 的拖动，落点能找到可配对且可见的牌。

死局处理：

- 弹出对话框：免费洗牌（推荐）、撤销、重开；
- 免费洗牌后重新检测；若仍死局（理论上极少），可继续洗牌或重开；
- 死局期间暂停计时与输入。

### 7.3 为什么可能死局

消除顺序会影响后续可见性；随机布局不保证存在一条通关路径。项目**不承诺**任意布局必然可解，而是通过：

- 初始生成时保证至少一个合法操作；
- 每步后的死局检测；
- 免费洗牌 + 撤销；

保证玩家不会卡死在无操作的状态。

> 后续可选：用“逆向摆牌”生成保证可解的布局（从空盘逐步放回可消除的对子），但实现复杂度较高，本期不做。

## 8. 边界情况清单

| # | 情况 | 行为 |
| --- | --- | --- |
| 1 | 两张同类牌相邻 | 可见，可直接点选消除 |
| 2 | 两张同类牌之间只有空格 | 可见，可消除（不要求相邻） |
| 3 | 两张同类牌之间有任何一张牌 | 不可见；点选不消除，锚牌切换 |
| 4 | 两张同类牌成对角 | 不可见 |
| 5 | 最后两张牌可配对 | 消除后立即胜利 |
| 6 | 拖动 `k = 0` | 视为点选，不消除 |
| 7 | 拖到边界 | `k` 被夹到 `kMax`，不越界 |
| 8 | 串头前方紧邻牌 | 该牌会被并入牌串（连续），不是阻挡 |
| 9 | 拖动失败 | 整串回原格，棋盘/步数/历史不变，锚牌保留 |
| 10 | 拖动成功但配对牌在牌串方向前方 | 不可能：牌串会先并入它；配对牌一定在异轴 |
| 11 | 锚牌与新位置可见 | 优先与锚牌配对，即使还有更近的候选 |
| 12 | 锚牌不可见/不可配对 | 自动选最近的可见同牌；不因锚牌失败而回弹 |
| 13 | 锚牌在移动牌串中 | 锚牌随串移动；落点判定后清空锚牌；配对牌不会是它 |
| 14 | 满盘 | 所有方向 `kMax = 0`，只能点选 |
| 15 | 只剩 2 张但不可配对 | 死局（理论上不会发生：张数成对且同种剩余） |
| 16 | 洗牌后仍死局 | 允许再次免费洗牌/撤销/重开 |
| 17 | 撤销到开局 | 棋盘恢复初始布局，`moves = 0`，计时不回退 |
| 18 | 重复点击同一张牌 | 取消选择 |
| 19 | 点击空白 | 取消选择 |
| 20 | 动画中点击 | 忽略（MVP） |
| 21 | 窗口失焦/切后台 | 暂停计时与渲染循环（可选，M5） |
| 22 | 触屏多指 | 只认第一根手指，其余忽略 |
| 23 | 拖动中反向 | `k` 夹到 0，不反向拖动 |
| 24 | 花牌跨组 | 不合法（春 ↔ 梅） |
| 25 | 花牌同组 | 合法（春 ↔ 秋、梅 ↔ 竹） |

## 9. 算法伪代码

以下为与实现无关的参考伪代码；TypeScript 实现应保持函数纯粹、无副作用。

### 9.1 生成

```
generate(mode, seed):
  kinds = KINDS[mode]
  bag = []
  for kind in kinds:
      repeat kind.count times: bag.push(kind.id)
  rng = mulberry32(seed)
  for attempt in 1..200:
      shuffle(bag, rng)
      board = fillRowMajor(bag, mode.rows, mode.cols)
      if findAnyMove(board) != null: return board
  return fallbackPairwiseLayout(mode)   // 见 §9.6
```

初始棋盘为满盘；`findAnyMove` 在满盘时等价于“存在相邻同类对”（因为任何非相邻牌之间都有牌阻挡）。

### 9.2 可见

```
visible(a, b):
  if a.row == b.row:
      for c in (min(a.col,b.col)+1 .. max(a.col,b.col)-1):
          if board[a.row][c] != null: return false
      return true
  if a.col == b.col:
      for r in (min(a.row,b.row)+1 .. max(a.row,b.row)-1):
          if board[r][a.col] != null: return false
      return true
  return false
```

### 9.3 牌串与滑动

```
segment(t, d):
  out = [t]; cur = t
  loop:
      n = cur + DELTA[d]
      if outOfBounds(n) or board[n] == null: break
      out.push(board[n]); cur = n
  return out

maxSlide(seg, d):
  n = seg.last + DELTA[d]; k = 0
  while inBounds(n) and board[n] == null:
      k += 1; n += DELTA[d]
  return k

slide(seg, k, d):
  copy = board.clone()
  for tile in reverse(seg):          // 逆序避免覆盖
      copy.move(tile, tile + d*k)
  return copy
```

### 9.4 选配对

```
choosePartner(board, dragged, anchor):
  cands = []
  for tile in board.tiles():
      if tile.id != dragged.id
         and compatible(dragged, tile)
         and visible(dragged, tile):
          cands.push(tile)
  if anchor != null and anchor in cands: return anchor
  if cands.empty: return null
  sort cands by (manhattan(dragged, t), t.row, t.col)
  return cands[0]
```

### 9.5 死局与提示

```
findAnyMove(board):
  // 1) 点选对子
  for each pair (a, b) in board.tiles():
      if compatible(a, b) and visible(a, b): return {kind:'tap', a, b}
  // 2) 拖动
  for each tile t:
      for d in DIRS:
          seg = segment(t, d)
          kmax = maxSlide(seg, d)
          for k in 1..kmax:
              preview = slide(seg, k, d)
              t2 = preview.tileAt(dest(t, k, d))
              p = choosePartner(preview, t2, null)
              if p != null: return {kind:'drag', tile:t, d, k, partner:p}
  return null
```

### 9.6 洗牌与兜底布局

```
shuffleRemaining(board, rng):
  positions = board.occupiedCells()
  kinds = positions.map(cell => board[cell].kindId)
  for attempt in 1..100:
      shuffle(kinds, rng)
      next = board.clone(); assign(next, positions, kinds)
      if findAnyMove(next) != null: return next
  return pairwiseFallback(positions, kinds)
```

`pairwiseFallback`：把相同牌种两两相邻地放入剩余位置（按行优先、蛇形），确保至少有一对相邻可消。仅作为极端兜底，正常不会触发。

### 9.7 复杂度

| 操作 | 复杂度 | 备注 |
| --- | --- | --- |
| 生成 | O(N) × 重试 | 重试通常 1 次 |
| 可见性 | O(max(R,C)) ≤ 12 | 极快 |
| 牌串/滑动 | O(max(R,C)) | 极快 |
| 单次落点配对 | O(N²) 最坏 | N ≤ 144，可忽略 |
| 死局检测 | O(N × 4 × D × N) 最坏 | 实测 < 1ms（D ≤ 12） |
| 撤销 | O(N) | 快照复制 |

## 10. 图例

### 10.1 点选配对

```
· 表示空格，字母表示牌种

A A · B          → A(0,0) 与 A(0,1) 相邻，可消除
A · · A          → 中间全空，可消除
A B · A          → B 阻挡，不可消除
A · B · A        → B 阻挡，不可消除
A · · ·          → 只有一张 A，不能消除
```

### 10.2 拖动牌串与滑动量

```
行：  ·  A  B  C  ·  ·  D
       ↑ 牌串起点（按下 A）
          └──── 牌串 A B C ────┘
                        └ 串头 C
C 右侧空格：2 个（kMax = 2）

k = 1： ·  ·  A  B  C  ·  D
k = 2： ·  ·  ·  A  B  C  D
```

### 10.3 同轴 / 异轴

```
行拖动（左右）改变列 → 只能产生“同列”的新配对（纵向）
列拖动（上下）改变行 → 只能产生“同行”的新配对（横向）
```

### 10.4 花牌

```
春 秋  ·  → 同属季节组，可消除
春 梅  ·  → 跨组，不可消除
梅 竹  ·  → 同属花组，可消除
```
